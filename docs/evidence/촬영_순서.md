# 증거 스크린샷 촬영 순서 (A13)

대상: https://webtest-passkey.vercel.app
저장 위치: `docs/evidence/` · 파일명은 아래 그대로 (색인은 `docs/evidence/README.md`)

## ⚠️ 찍기 전에

- **비공개 항목에는 지어낸 내용만 넣는다.** 실제 연락처·주소·신분증 번호 금지.
- **Network 탭 스크린샷에서 Request Headers 의 `Cookie:` 줄은 접거나 가린다.**
  `to8_session` 원문이 보이면 C34(세션 값 가려짐) 위반이다. Payload/Response 탭만 펼치면 안전.
- 4번(실기기 등록)과 5번(가상 인증기)은 **순서를 지켜야 한다.** 가상 인증기를 켜면 실제 지문/PIN
  프롬프트가 안 뜬다.

## 1단계 — 시크릿 창 (아무것도 등록하지 않은 상태)

`Ctrl+Shift+N` 새 시크릿 창.

**① `T08-E01-public-incognito.png`** — 공개 소개가 로그인 없이 열리는 화면
- 주소창에 `webtest-passkey.vercel.app` 이 보이게
- 이름 "홍주형" + 소개 문장이 보이게
- 아래로 스크롤해 **"공개 범위"** 섹션의 노란 점선 고지문
  ("이 소개 페이지의 내용은 학습·연습용으로 지어낸(fabricated) 것입니다…")이 같은 창에 보이게
  (한 화면에 다 안 들어오면 2장으로 나눠 `-a`, `-b` 접미사)
- → C10, C11, C12

**② `T08-E02-private-redirect.png`** — 잠겨 있음
- 주소창에 `/private` 을 직접 입력 → `/login` 으로 넘어가고 "비공개 영역 / 비밀번호는 없습니다" 화면이 뜸
- 이 상태에서 `Ctrl+U`(페이지 소스) → `Ctrl+F` 로 `회고` 또는 `프로젝트 메모` 검색 →
  **0건**인 것이 보이게 (검색 결과 카운터가 나오게 찍는다)
- → C15, C18

시크릿 창은 여기서 닫는다.

## 2단계 — 실제 기기 패스키 → **휴대폰에서** 한다

> 이 PC 에는 Windows Hello(지문·얼굴·PIN)가 등록돼 있지 않아 Windows 가 USB 보안 키만 제시한다.
> 로그인 화면에도 그 안내가 뜬다. **휴대폰(안드로이드 Chrome / 아이폰 Safari)으로**
> `webtest-passkey.vercel.app` 을 열어 등록하면 구글 비밀번호 관리자 · iCloud 키체인으로 저장된다.
> (PC 에서 하고 싶으면 Windows 설정 → 계정 → 로그인 옵션에서 PIN 을 먼저 만들면 된다.)
>
> 이 화면 캡처는 휴대폰 스크린샷으로 찍어 PC 로 옮긴다.

**DevTools 는 아직 열지 않는다.**

`/login` → 하단 "새로 만들 패스키 이름 (비밀번호 아님)" 에 예: `내 노트북` 입력 →
**[패스키로 비공개 자리 만들기]** 클릭.

**③ `T08-E03-register-prompt.png`** — 기기가 열쇠를 만드는 순간
- 구글 비밀번호 관리자 / iCloud 키체인 프롬프트가 뜬 화면 (휴대폰 스크린샷)
- 뒤에 사이트가 보이면 좋다
- → C25, C26

지문/PIN 으로 승인하면 비공개 영역으로 들어간다.

**④ `T08-E05-private-items.png`** — 비공개 항목 3건
- "새 항목 입력" 칸에 **지어낸** 항목 3개 이상 추가. 예:
  - `준비 중: 공조냉동 필기 오답노트 정리`
  - `지원 목록: 설비관리 3곳, IT 헬프데스크 1곳`
  - `이번 주 회고: 패스키 붙이면서 rpID 도메인 바인딩을 처음 이해함`
- 상단 **"🔒 비공개 영역 · 나만 볼 수 있습니다"** 라벨과 그 위 구분선이 함께 보이게
  (공개/비공개 경계가 한 화면에 보여야 C13)
- → C13, C14

## 3단계 — 등록·로그인 요청 본문 (PC 일반 창)

> 3·4단계는 PC 에서 한다. 4단계의 가상 인증기가 실기기 없이도 등록·로그인을 처리해 주므로
> Windows Hello 가 없어도 문제없다. 3단계 요청 본문은 4단계에서 가상 인증기로 등록/로그인하며 같이 찍어도 된다.


`F12` → **Network** 탭 → `Fetch/XHR` 필터.

**⑤ `T08-A02-network-register-verify.png`**
- 페이지에서 **[다른 패스키 등록]** 을 눌러(프롬프트 취소해도 됨) 또는 위 2단계 등록 직후 기록에서
  `register/verify` 요청 선택 → **Payload** 탭 펼치기
- `attestationObject`, `clientDataJSON`, `transports` 만 있고 **개인키가 없다**는 게 보이게
- Headers 탭은 펼치지 말 것(쿠키 노출)
- → C23

**⑥ `T08-A04-network-authenticate.png`**
- 로그아웃 → **[패스키로 로그인]** → `authenticate/verify` 요청 → **Payload** 탭
- `signature`, `authenticatorData`, `userHandle` 이 보이게
- → C29

## 4단계 — 가상 인증기로 "두 기기" (같은 창)

`F12` → 우측 점 3개 `⋮` → **More tools** → **WebAuthn** → `Enable virtual authenticator environment` 체크.

**Add authenticator**: Protocol `ctap2` / Transport `internal` / Resident keys **Yes** / User verification **Yes** → 추가.

로그인한 상태에서 비공개 영역 → **[다른 패스키 등록]** (프롬프트 없이 가상 인증기가 즉시 처리).

**⑦ `T08-E04-passkey-list.png`** — 패스키 목록 2행
- "등록된 패스키" 패널에 **2개**가 이름 + `등록: 2026-09-04 …` + 저장 위치 문구와 함께 보이게
- → C24, C42, C43

**⑧ `T08-A01-devtools-webauthn.png`** — 삭제 후에도 들어가지는 것
- 목록에서 첫 번째 패스키 **[삭제]** → "패스키를 삭제했습니다. 남은 패스키로 계속 로그인할 수 있습니다." 메시지
- **[로그아웃]** → **[패스키로 로그인]** → 남은 패스키로 성공해서 비공개 영역이 다시 열림
- 이 화면과 DevTools **WebAuthn 탭의 credential 목록**이 같이 보이게 찍는다
- 이어서 남은 하나를 **[삭제]** 시도 → 빨간 메시지
  "마지막 패스키는 삭제할 수 없습니다…" 가 뜨는 것도 같은 장 또는 `-b` 로 한 장 더
- → C42, C44, C45, C46

끝나면 WebAuthn 탭의 `Enable virtual authenticator environment` 체크를 **해제**한다.

## 5단계 — 서버에 저장된 것이 공개키임을 보이기

Vercel 대시보드 → 프로젝트 `webtest-passkey` → **Storage** → Redis → **Data Browser**.

**⑨ `T08-A03-redis-cred.png`**
- `cred:` 로 시작하는 키 하나를 열어 값(JSON)이 보이게
- `publicKey` 필드가 있고 **비밀번호/해시 필드가 없다**는 게 보이게
- 같은 화면에 `challenge:` 키가 함께 보이면 C19 근거로도 쓰인다
- → C21, C22
