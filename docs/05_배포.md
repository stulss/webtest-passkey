# 05. 배포 (과제 8)

## 배포처 선택

| 후보 | 판단 |
|---|---|
| **Vercel + Upstash Redis (선택)** | Next.js 기본 빌드 그대로. Storage 탭에서 Redis 통합 1번이면 자격증명 자동 주입. challenge TTL·1회 소비가 Redis 명령 그대로 |
| GitHub Pages (과제 1 배포처) | 정적 전용 → challenge 발급·검증·세션 불가. 제외 |
| Vercel + Supabase Postgres | 동작하지만 `schema.sql`·접속 문자열 2종·풀러 설정이 이 규모엔 과함 |
| Render / Fly + SQLite | 무료 티어 spin-down. 워크스페이스 선례는 Vercel |

원본 `webtest` 저장소와 그 GitHub Pages 배포(`stulss.github.io/webtest/`)는 **건드리지 않는다.**
과제 8은 새 저장소·새 Vercel 프로젝트로 나간다.

## 순서

1. **로컬 저장소**
   ```bash
   cd to8
   git init && git branch -m main
   git add -A && git commit -m "과제 8: 패스키로 잠근 소개 페이지"
   ```
   `.gitignore` 에 `.env*` 가 있는지 먼저 확인(이미 포함).

2. **GitHub** — 새 public 저장소 생성 후
   ```bash
   git remote add origin https://github.com/stulss/<repo>.git
   git push -u origin main
   ```

3. **Vercel** — New Project → 위 저장소 import. 프레임워크 `Next.js` 자동 감지. `vercel.json` 없음.

4. **Upstash Redis 통합** — Vercel 프로젝트 → **Storage** 탭 → Redis(Upstash) 생성 → 이 프로젝트에 Connect.
   `KV_REST_API_URL`, `KV_REST_API_TOKEN`(+ read-only) 이 Production·Preview·Development 에 자동 주입된다.
   (통합에 따라 `UPSTASH_REDIS_REST_URL/TOKEN` 이름일 수 있음 — 코드가 둘 다 지원.)

5. **WebAuthn 환경변수** — Vercel 프로젝트 → Settings → Environment Variables (Production + Preview):
   | 이름 | 값 |
   |---|---|
   | `WEBAUTHN_RP_ID` | `<프로덕션 도메인>` — 스킴·포트·경로 없이. 예: `to8-abc123.vercel.app` |
   | `WEBAUTHN_ORIGIN` | `https://<프로덕션 도메인>` |
   `NEXT_PUBLIC_*` 는 쓰지 않는다. 세션 서명키도 없다(불투명 토큰).

6. **첫 배포 → URL 확정 → 재배포** — Vercel 이 프로덕션 도메인을 확정하면 5의 두 값을 그 도메인으로
   맞추고 다시 배포한다. (프리뷰 도메인은 배포마다 바뀌므로, 프리뷰에서 만든 패스키는 프로덕션에서
   통하지 않는다 — 정상 동작.)

7. **동작 확인** — 새 시크릿 창에서 프로덕션 URL:
   - `/` 공개 소개가 로그인 없이 열림 (C01–C12)
   - `/private` → `/login` 리다이렉트, 페이지 소스에 비공개 항목 없음
   - 플랫폼 인증기로 [패스키로 비공개 자리 만들기] → 비공개 영역, 항목 3건 추가

8. **배포본 자동 검증**
   ```bash
   vercel env pull .env.local
   APP_URL=https://<프로덕션> WEBAUTHN_RP_ID=<도메인> node --env-file=.env.local scripts/verify-webauthn.mjs
   ```
   `docs/evidence/*` 가 배포 기준으로 갱신된다. 검증 계정·항목은 스크립트가 스스로 정리하지 않으므로
   (실 Redis), 필요하면 Upstash 콘솔에서 `space:*` `cred:*` `item:*` `session:*` `challenge:*` 키를 지운다.

## 운영 주의

- `challenge:audit` 는 최근 200개로 capped(`LTRIM`). 그 외 challenge 키는 5분 TTL 로 자동 소멸.
- 패스키는 정확한 도메인에 묶인다. 커스텀 도메인을 붙이면 `WEBAUTHN_*` 을 다시 맞춰야 하고,
  기존에 등록된 패스키는 무효가 된다.
- 쿠키 `Secure` 는 `NODE_ENV==="production"` 에서 자동. WebAuthn 은 secure context(HTTPS 또는 localhost)에서만 동작.
