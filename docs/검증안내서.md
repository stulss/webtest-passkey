# 검증 안내서 (과제 8)

## 짧은 확인 4줄

| | |
|---|---|
| **① 어디로 가나요** | 배포 주소 https://webtest-passkey.vercel.app 를 새 시크릿 창에서 엽니다. (심사자는 공개 소개까지만 보면 됩니다.) |
| **② 세 단계 안에 무엇을 하나요** | (1) 첫 화면에서 공개 소개를 봅니다 → (2) 주소창에 `/private` 를 칩니다 → (3) [패스키로 비공개 자리 만들기] 를 누르고 기기 인증(지문·PIN·기기 잠금해제)을 합니다. |
| **③ 무엇이 보이면 통과인가요** | (1) 공개 소개(이름·소개 문장·공개 범위·"지어낸 내용" 고지), (2) `/private` 은 잠겨 있어 로그인 화면이 뜨고 **비공개 항목 텍스트는 화면에도 페이지 소스에도 없음**, (3) 패스키를 만든 뒤에만 내 비공개 항목과 패스키 목록이 보임. 다른 사람 항목은 0건. |
| **④ 안 될 때는 무엇이 보이나요** | 패스키 창이 안 뜨면 주소가 `https` 인지(개발은 `localhost` 만 예외) 확인. 로그인 없이 `/private` 로 가면 `/login` 으로 넘어가고 `GET /api/items` 는 `401 {"error":"로그인이 필요합니다."}`. 로그아웃 뒤 이전 세션으로 다시 요청해도 `401`. 이미 쓴 인증 요청을 재사용하면 `400 "인증 요청이 만료되었거나 이미 처리되었습니다"`. 남의 패스키·남의 항목 주소로는 `400`/`404`. |

> 심사 참고: 공개 소개 페이지만 보면 됩니다. 잠긴 자리는 열지 않아도 됩니다.
> 비공개 자리에 넣는 내용은 만들어 넣은 것이며 실제 개인정보가 아닙니다.

## Chrome DevTools 가상 인증기로 "두 기기" 확인 (C42~C46)

1. `F12` → 점 3개 → More tools → **WebAuthn** → "Enable virtual authenticator environment".
2. **Add authenticator**: Protocol `ctap2`, Transport `internal`, Resident keys **Yes**, User verification **Yes** → 기기 #1.
3. 다시 **Add authenticator** → 기기 #2 (Transport 를 `usb` 로 두면 "보안 키" 문구도 확인됨).
4. `/private` → [패스키로 비공개 자리 만들기] (기기 #1) → [다른 패스키 등록] 으로 기기 #2 등록 →
   목록에 2행(이름 + 등록 날짜)이 보임.
5. 기기 #1 패스키 [삭제] → 로그아웃 → 기기 #2 로 로그인 성공 → 기기 #1 credential 로는 로그인 불가.
6. 스크린샷: WebAuthn 탭의 credential 목록 / Network 탭의 `register/verify`·`authenticate/verify` 요청 본문
   (attestationObject·clientDataJSON·signature 만 있고 개인키 없음) / Redis 콘솔(Data Browser)의 `cred:*` 값
   (COSE 공개키 — `kty:EC2, alg:-7, crv:P-256, x, y`. 비밀번호 아님).
