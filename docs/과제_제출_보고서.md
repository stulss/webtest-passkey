## 2. 1번(webtest)에서 이어 만든 내용

- 과제 1의 `webtest`(정적 Vanilla JS MVC, GitHub Pages)를 Next.js 16 App Router 로 옮겼다.
- 공개 콘텐츠(`홍주형` 프로필, 강점 3·기술·프로젝트·공개 범위)는 `app/portfolio-data.ts` 로 그대로 이식.
  1번의 공개 내용이 그대로 남아 있다.
- 새로 만든 것: `/private` 비공개 영역 + `/login` + `/api/*` 서버 라우트.
- 소개 페이지 내용은 만들어 넣은(fabricated) 것이며 실제 개인정보가 없다. 공개 페이지 하단에 그 사실을 고지한다.

## 4. 검증 결과

`node scripts/verify-webauthn.mjs` (소프트웨어 인증기) — **전 항목 통과** (`docs/evidence/webauthn-verify-results.json`):

| 확인 | 성공 | 거절 |
|---|---|---|
| challenge 매번 다름 | 등록 5 + 로그인 5 = 10개 상이 | — |
| 서명 검증 | 정상 서명 → 200 | 1바이트 변조 서명 → 401 |
| challenge 재사용 | 첫 사용 → 200 | 재사용 → 400 |
| 미로그인 조회 | 로그인 후 → 200 (3건) | 쿠키 없이 → 401, `/private` → 307 |
| 로그아웃 후 재사용 | — | 이전 세션 쿠키 → 401 |
| 패스키 2개 → 삭제 | 남은 패스키 로그인 → 200 | 삭제된 패스키 → 400, 마지막 삭제 → 409 |
| 자리 간 격리 | 각 자리 자기 항목 생성 → 201 | A↔B 양방향 → 404, 건수 3→3 불변, 스푸핑 쿼리 무시 |

`npm run typecheck` 통과 · `npm test` 8/8 통과.

남은 것(사용자 콘솔·촬영): 배포, 실기기 패스키 등록 스크린샷, DevTools 가상 인증기 2개 스크린샷,
배포 URL 로 `verify-webauthn.mjs` 재실행. 절차 `docs/05_배포.md`·`docs/검증안내서.md`.

## 6. 아직 못 막은 것 (최소 1개)

**모든 등록 기기를 잃으면 그 비공개 자리와 항목에 영원히 접근할 수 없다.** 이메일·복구코드가 없다.
패스키를 2개 이상 등록해 한 기기 분실은 견디지만, 전부 잃는 경우의 복구는 이 과제 범위 밖으로 두었다.
나머지 5가지는 `docs/인증_구현_설명서.md` ⑥.
