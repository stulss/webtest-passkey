# 포트폴리오 추가용 소개글 (과제 8)

## 한 줄

비밀번호 없이, 등록한 기기만 열쇠가 되는 비공개 영역을 개인 소개 페이지에 붙였습니다. (WebAuthn 패스키)

## 4~5줄

과제 1에서 만든 정적 소개 페이지를 Next.js로 옮기고, `/private` 라는 나만의 자리를 패스키로 잠갔습니다.
등록할 때 기기가 열쇠 한 쌍을 만들어 공개키만 서버로 보내고, 로그인할 때는 서버가 매번 새 질문(challenge)을
보내 기기가 서명으로 답합니다. 서버는 저장해 둔 공개키로 그 서명을 확인한 뒤에만 문을 엽니다.
기기를 잃을 때를 대비해 패스키를 두 개 등록해 두고 하나를 지워도 들어갈 수 있게 했으며, 남의 패스키로는
열리지 않고 자리마다 자료가 완전히 분리되는 것을 요청·응답 기록으로 남겼습니다. 공개 소개는 지금처럼
누구나 봅니다.

## 무엇을 직접 붙였나 (계층)

```
브라우저   @simplewebauthn/browser  →  navigator.credentials (기기가 키쌍 생성·서명)
   │
프록시     proxy.ts                 →  쿠키 유무 1차 관문
API        app/api/webauthn/*       →  challenge 발급·검증, 세션 발급
서비스     lib/service/*            →  등록·로그인·격리 흐름 조립
저장소     lib/repository/*         →  Redis 키 (challenge · cred(공개키) · session · item)
검증       @simplewebauthn/server   →  attestation/assertion 서명 검증
```

## 면접 질문 → 답

| 질문 | 답 |
|---|---|
| 비밀번호를 안 쓰면 뭐가 그 자리를 채우나요? | 기기 안의 개인키와, 서버가 매번 새로 보내는 일회용 challenge, 그리고 서버에 저장된 공개키입니다. 개인키는 기기 밖으로 나오지 않습니다. |
| 이미 쓴 challenge 를 다시 쓰면? | 서버가 `GETDEL` 로 challenge 를 원자적으로 한 번만 소비합니다. 두 번째 요청은 값이 없어 400 입니다. |
| 로그인 뒤에는 뭘로 사람을 알아보나요? | 불투명 난수 세션입니다. 쿠키에 원문, 서버에는 sha256 해시만 둡니다. 로그아웃하면 서버 키를 지워 즉시 무효화됩니다. |
| 기기를 잃으면요? | 패스키를 두 개 이상 등록해 두면 하나를 지워도 나머지로 들어갑니다. 다만 전부 잃으면 복구 수단이 없습니다(이 과제의 한계로 밝혔습니다). |
| 남의 자료는 어떻게 막나요? | 자리 ID 를 세션 쿠키에서만 얻고, 저장소 함수가 항상 그 자리 키만 만듭니다. 단건 삭제는 소유자 확인 후에만 실행하고, 아니면 존재를 숨기려 404 를 돌려줍니다. |
